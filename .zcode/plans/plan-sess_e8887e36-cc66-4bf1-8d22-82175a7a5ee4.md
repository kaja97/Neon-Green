## Bug 4 — Weather "unavailable" / "Failed to load"
**Root cause (confirmed):** The backend wraps every response in `{success, data, meta}`. `WeatherBlock.tsx` and `WeatherCardBlock.tsx` use `res.data` (the whole envelope) instead of `res.data.data`. So `weather` becomes the envelope object → `weather.current` is undefined → block shows "Failed to load"/"Weather unavailable". The weather backend itself is fine (it reads the project's location centroid + the OpenWeather API key in `.env`).

**Fixes:**
- `frontend/components/blocks/WeatherBlock.tsx`: `return res.data;` → `return res.data.data;`
- `frontend/components/blocks/WeatherCardBlock.tsx`: same one-line fix.
(Weather page already uses `res.data.data` correctly — no change there.)

## Bug 5 — Disease count always shows 1 or 0
**Root cause (confirmed):** The Disease tile on the project page reads `active_issues` from the **cached dashboard** (Redis, TTL 180s). The disease service `report_issue()` and `resolve_issue()` mutate issues but **never invalidate the dashboard cache**, so the count stays stale for up to 3 minutes — appearing "stuck" at 1 or 0. (The query itself is correct: `status != "resolved"`.)

**Fix:** Add `invalidate_dashboard_cache(str(project_id))` (wrapped in try/except, matching the pattern in `project/service.py`) to:
- `backend/modules/disease/service.py` → `report_issue()` (after commit)
- `backend/modules/disease/service.py` → `resolve_issue()` (after commit)
Also remove the now-unused `DiseaseBlock` import in the project page (dead import; the tile is built inline).
