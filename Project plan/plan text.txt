The Architectural BlueprintThe Core LLM Application: A centralized reasoning engine (such as a hosted Claude model) connects dynamically to individual farmer endpoints via MCP.The Localized MCP Server: Each farmer’s profile and active projects expose standard JSON-RPC endpoints compliant with the Model Context Protocol. This architecture enables the primary LLM to securely read a farmer's historical data, soil status, and exact crop calendar without forcing all that raw information into the system prompt context window for every generic turn.The Multi-Tiered Vector Space:Tier 1 (Global/Regional): General plant science, disease indices, and treatment alternatives (organic vs. inorganic).Tier 2 (Farmer/Project Private): Specific historical actions, unique soil test metrics, and geo-coordinates.Data Synchronization FlowThe core application sends a user query along with a location token to the backend orchestrator.The orchestrator uses the farmer's private MCP server to pull current local context: soil metrics from database tables, localized weather telemetry, and current growth cycle stage.This contextual data is packaged dynamically into structured function calls, completely avoiding the need for an open-ended, multi-agent conversational loop for everyday lookups.3. 1. User & Profile ManagementSQLCREATE TYPE user_role AS ENUM ('farmer', 'middleman', 'vendor', 'admin');
CREATE TYPE farming_method AS ENUM ('organic', 'inorganic', 'hybrid');

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    role user_role NOT NULL DEFAULT 'farmer',
    preferred_language VARCHAR(5) DEFAULT 'si', -- 'si' (Sinhala), 'ta' (Tamil), 'en' (English)
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE farmer_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES users(id) ON DELETE CASCADE,
    full_name VARCHAR(255) NOT NULL,
    preferred_method farming_method NOT NULL DEFAULT 'hybrid',
    experience_years INT DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
2. Geo-Spatial Farm & Crop Project SetupSQLCREATE TABLE farm_lands (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    farmer_id UUID REFERENCES farmer_profiles(id) ON DELETE CASCADE,

CREATE TABLE farm_projects (

    scale_unit VARCHAR(20) NOT NULL,    -- 'plants', 'acres', 'hectares'

    current_stage_day INT DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

4. Core Service Logic & Deterministic EngineTo optimize API operation costs, the application runs on a deterministic service engine written in native Python code. This avoids expensive LLM calls for day-to-day scheduling calculations.Service 1: Weather-Driven Smart Irrigation EngineThis engine calculates irrigation windows by evaluating rain patterns, saving water and avoiding nutrient washout from fertilizer applications.Pythonimport datetime
from typing import Dict, Any

class WeatherIrrigationEngine:
    def __init__(self, db_connection, weather_api_client):
        self.db = db_connection
        self.weather_api = weather_api_client

    def calculate_irrigation_necessity(self, project_id: str) -> Dict[str, Any]:
        # 1. Fetch project profile and location coordinates
        project = self.db.fetch_project_with_location(project_id)
        centroid = project["centroid"] # Geo-coordinates
        
        # 2. Extract telemetry via Weather API
        # Fetches a 5-day predictive forecast window
        forecast_5_day = self.weather_api.get_forecast(lat=centroid.y, lon=centroid.x)
        
        total_predicted_rainfall_mm = sum(day["rain_mm"] for day in forecast_5_day[:5])
        will_rain_imminently_24h = forecast_5_day[0]["rain_probability"] > 0.70
        
        # 3. Retrieve baseline metrics for the specific crop
        crop_water_need = project["water_requirement_index"] # Factor rating (1-5 scale)
        last_watering_date = self.db.get_last_activity(project_id, activity_type="irrigation")
        days_since_water = (datetime.date.today() - last_watering_date).days if last_watering_date else 99
        
        # Deterministic Decision Rule Tree
        decision = {
            "action_required": True,
            "reasoning": "Standard lifecycle interval reached.",
            "water_volume_liters_per_unit": crop_water_need * 1.5
        }
        
        if will_rain_imminently_24h:
            decision["action_required"] = False
            decision["reasoning"] = "Heavy precipitation forecast within the next 24 hours. Postponing irrigation to preserve root health."
        elif total_predicted_rainfall_mm > 25.0:
            decision["action_required"] = False
            decision["reasoning"] = "Substantial cumulative rainfall expected across the 5-day matrix; natural hydration is sufficient."
        elif days_since_water < 2 and crop_water_need < 4:
            decision["action_required"] = False
            decision["reasoning"] = "Soil profile dampness index is within the green target threshold based on recent watering history."
            
        return decision
Service 2: Structural Crop Lifecycle & Fertilizer SchedulerThis engine map steps throughout a crop's natural growth cycle, adjusting instructions according to whether the farm uses organic or inorganic methods.Pythondef generate_crop_timeline_schedule(project_id: str, database_session) -> list[dict]:
    # Retrieve project data joined with crop templates and user profile preferences
    meta = database_session.query_project_metadata(project_id)
    
    start_date = meta["start_date"]
    total_days = meta["base_lifecycle_days"]
    farming_type = meta["preferred_method"] -- 'organic' | 'inorganic'
    
    schedule_timeline = []
    
    # Sequential milestone distribution logic loops
    for day in range(0, total_days + 1):
        current_date = start_date + datetime.timedelta(days=day)
        percent_complete = (day / total_days) * 100
        
        # Phase 1: Emergence & Early Ground Establishment (First 15%)
        if day == 0:
            schedule_timeline.append({
                "target_day": day, "date": current_date, "category": "Planting",
                "task": "Sow seeds or plant seedlings into prepared beds.",
                "importance": "critical"
            })
        elif percent_complete >= 10.0 and percent_complete <= 12.0:
            fertilizer = "Liquid compost tea or seaweed extract" if farming_type == "organic" else "NPK Starter Blend (High Nitrogen)"
            schedule_timeline.append({
                "target_day": day, "date": current_date, "category": "Fertilization",
                "task": f"Apply first round of root-boosting feed: Use {fertilizer}.",
                "importance": "high"
            })
            
        # Phase 2: Vegetative Growth Framework (15% to 50%)
        elif percent_complete >= 30.0 and percent_complete <= 32.0:
            fertilizer = "Well-rotted poultry manure mix" if farming_type == "organic" else "Urea / Nitrogen boost application"
            schedule_timeline.append({
                "target_day": day, "date": current_date, "category": "Fertilization",
                "task": f"Apply structural vegetative fertilizer: Use {fertilizer}.",
                "importance": "medium"
            })
            
        # Phase 3: Flowering & Fruit Production (50% to 85%)
        elif percent_complete >= 60.0 and percent_complete <= 62.0:
            fertilizer = "Wood ash extract / Bone meal infusion" if farming_type == "organic" else "Muriate of Potash (MOP) high-potassium treatment"
            schedule_timeline.append({
                "target_day": day, "date": current_date, "category": "Fertilization",
                "task": f"Apply bloom and fruit-set enhancement: Use {fertilizer}.",
                "importance": "high"
            })
            
    return schedule_timeline
